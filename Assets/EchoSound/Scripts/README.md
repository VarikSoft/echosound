# Как ориентироваться в скриптах

Читайте в таком порядке:

1. **Generation/LevelGenerator.cs → Generate()** — главный сценарий: построить карту, выбрать префабы, поставить комнаты, отправить событие.
2. **Generation/RoomGraph.cs** — алгоритм карты. `BuildConnectedRooms` добавляет связанные комнаты, `AddExtraConnections` создаёт обходные пути. Здесь нет GameObject и игрока.
3. **Rooms/RoomCatalog.cs → Pick()** — выбор префаба по входам, повороту и весу.
4. **Rooms/RoomTemplate.cs** — сведения о префабе: название, размер, безопасный Anchor и дочерние входы.
5. **Testing/GenerationPlayground.cs** — связывает тестовую сцену с генератором и игроком.
6. **Player/FirstPersonPlayer.cs** — камера, ходьба, бег, прыжок и перенос игрока.

Дополнительные небольшие файлы:

| Файл | Назначение |
|---|---|
| Generation/GeneratedLevel.cs | Результат генерации: карта и размещённые комнаты |
| Rooms/DoorLayout.cs | Четыре стороны света, флаги входов и их повороты |
| Rooms/RoomDoor.cs | Маркер одного входа и его Gizmos |
| Rooms/RoomMarker.cs | Подписанные точки для будущих секретов, загадок и монстров; без игровой логики |

Объекты комнат и внутренние проходы настраиваются в **префабах**, а не в этих скриптах. Новые варианты добавляются в **DefaultRooms.asset**.

Скриптов мини-карты, артефактов, фонаря и интерфейса здесь нет. Настройка редактора и проверки находятся отдельно в `../Editor`.

## AI-компаньон (локальная LLM через Ollama)

Компаньон слушает куратора (игрока), а LLM выбирает функции из доступных. Двигается компаньон сам, через NavMesh: LLM только решает, что делать.

**Игрок и компаньон пользуются объектами одинаково.** Правила (дистанция, «уже открыта», «в проёме кто-то стоит») записаны один раз в объекте. И клавиша E игрока, и функция LLM вызывают один и тот же `Interactable.TryUse`. Разница только в способе: игрок подходит сам и смотрит на объект, компаньон сначала идёт к нему по NavMesh.

Читайте в таком порядке:

1. **Interaction/Interactable.cs → TryUse()** — единственный вход для любого взаимодействия: проверка дистанции, проверка правил объекта (`CanPerform`), действие (`Perform`). Позже здесь же будет шум для врагов.
2. **Interaction/Door.cs** — раздвижная дверь: действия `Open` и `Close` и их правила. Пока дверь закрыта, она вырезает дыру в NavMesh, поэтому маршрут через неё недоступен.
3. **Interaction/Interactor.cs** — «руки»: этот компонент есть и у игрока, и у компаньона.
4. **Player/PlayerInteractor.cs** — клавиша E: луч из камеры, затем `TryUse` с основным действием объекта.
5. **Companion/CompanionBrain.cs → Command() и Handle()**. Приказ отправляется в LLM вместе с описанием того, что видит компаньон. Выбранные функции выполняются по очереди, их результаты возвращаются в LLM, и так до словесного ответа. Новый приказ прерывает текущий.
6. **Companion/UseObjectTool.cs** — функции для объектов (`open_door`, `close_door`). Они создаются на каждый запрос из того, что компаньон видит. Функция проверяет правила объекта, идёт к ближней стороне и вызывает `TryUse`.
7. **Companion/CompanionTools.cs** — функции без объекта: `follow_curator`, `wait_here`, `go_to`.
8. **Companion/CompanionPerception.cs** — текст «что я вижу»: объекты рядом, их состояние и положение относительно куратора («впереди», «сзади», «слева»).
9. **Companion/CompanionAgent.cs** — тело компаньона: ходьба по NavMesh, следование за куратором, обнаружение застревания.
10. **Companion/OllamaClient.cs** — запрос к `/api/chat` с tools.
11. **Testing/CompanionPlayground.cs** — тестовая сцена: после каждой генерации запекает NavMesh, ставит двери в проёмы и размещает компаньона рядом с игроком.

**Новый вид объекта** (рычаг, кнопка, терминал) — это подкласс `Interactable`. Если нужно новое действие, добавьте его в `InteractionAction` (например, `Pull`). Код компаньона менять не нужно: функция `pull_lever` появится у LLM сама, а клавиша E у игрока заработает сразу.

**Новая способность компаньона без объекта** (например, «пингануть камеру») — это подкласс `CompanionTool`, добавленный в `CompanionBrain.CreateFixedTools()`. Список id в аргументах пересобирается на каждый запрос, поэтому модель не может придумать несуществующий объект.

**Запуск:** `ollama serve`, затем модель с поддержкой tools (по умолчанию `qwen3.5:9b`, меняется в Inspector у `CompanionBrain`). Выберите меню **EchoSound → Create companion test scene** и нажмите Play. Enter открывает поле приказа, E открывает и закрывает дверь самому игроку. Меню добавляет `PlayerInteractor` только игроку этой сцены. Чтобы игрок мог пользоваться объектами везде, примените override к `FirstPersonPlayer.prefab`.
